## 1. Architecture Overview

```
┌─────────────────────────────────────────────────────────────┐
│                    Frontend (React + Vite)                  │
│  Port 5173/5174 │ Context API │ WebSocket (SockJS+STOMP)   │
└─────────────────────────────┬───────────────────────────────┘
                              │ HTTP/REST + WS
┌─────────────────────────────▼───────────────────────────────┐
│                  Backend (Spring Boot 4.0.5)                │
│  Port 8080 │ JPA/Hibernate │ Stripe SDK │ WebSocket Broker │
└─────────────────────────────┬───────────────────────────────┘
                              │ JDBC
┌─────────────────────────────▼───────────────────────────────┐
│              PostgreSQL (project_showcasing)                │
└─────────────────────────────────────────────────────────────┘
```

**Key Components:**
- **Frontend:** React with Context API for global state, react-bootstrap UI, SockJS+STOMP for real-time updates, JWT auth
- **Backend:** Spring Boot REST controllers, JPA repositories, embedded Tomcat, WebSocket message broker, Spring Security with JWT
- **Payment:** Stripe Checkout Sessions + Webhook events for payment confirmation
- **Real-time:** WebSocket broadcasts order/payment status updates to subscribed clients
- **Auth:** JWT-based authentication with USER/ADMIN roles; role-based endpoint access control

## 3. Database Schema

### Tables Overview

```sql
-- users (NOT YET IMPLEMENTED)
-- CREATE TABLE users (...);

-- products
CREATE TABLE products (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    brand VARCHAR(255),
    price DECIMAL(10,2) NOT NULL,
    category VARCHAR(255),
    release_date DATE,
    product_available BOOLEAN DEFAULT true,
    stock_quantity INTEGER NOT NULL DEFAULT 0,
    image_url VARCHAR(500),
    delete_hash VARCHAR(255)
);

-- orders
CREATE TABLE orders (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    user_id VARCHAR(255),           -- Will link to users table later
    order_date TIMESTAMP NOT NULL,
    total_amount DECIMAL(10,2) NOT NULL,
    status VARCHAR(50) NOT NULL,    -- PENDING, PAID, FAILED, CANCELLED, REFUNDED
    stripe_session_id VARCHAR(255) UNIQUE,
    stripe_payment_intent_id VARCHAR(255),
    customer_email VARCHAR(255),
    shipping_address TEXT,
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL
);

-- order_items
CREATE TABLE order_items (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    order_id BIGINT NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    product_id INTEGER NOT NULL,
    product_name VARCHAR(255) NOT NULL,
    product_brand VARCHAR(255),
    product_image_url VARCHAR(500),
    quantity INTEGER NOT NULL,
    unit_price DECIMAL(10,2) NOT NULL,
    subtotal DECIMAL(10,2) NOT NULL
);

-- payments
CREATE TABLE payments (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    order_id BIGINT UNIQUE NOT NULL REFERENCES orders(id),
    stripe_session_id VARCHAR(255),
    stripe_payment_intent_id VARCHAR(255),
    amount DECIMAL(10,2) NOT NULL,
    currency VARCHAR(3) DEFAULT 'usd',
    status VARCHAR(50) NOT NULL,    -- PENDING, SUCCEEDED, FAILED, REFUNDED, CANCELLED
    payment_method VARCHAR(50),
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL
);
```

### Entity Relationships

- **Order** → **OrderItem**: One-to-many (cascade ALL)
- **Order** → **Payment**: One-to-one (bidirectional, Payment owns FK)
- **OrderItem** → **Product**: Many-to-one (Product ID stored in OrderItem, but Product entity not directly linked)
- **Product** is standalone (no direct order link)

## 5. Frontend Architecture

### State Management
- **Context API**: `AppProvider` holds global state: `data` (products), `cart`, `isError`, `refreshData`
- **WebSocketContext**: Manages WebSocket connection, `orderUpdates`, `paymentUpdates`, `subscribeToOrder`
- **Local Component State**: Used for UI-specific state (modals, forms, page-specific data)

### Component Structure
```
App
├── AppProvider (Context)
│   ├── Navbar (shows Admin link if isAdmin)
│   ├── Routes
│   │   ├── Home (products grid, category filter)
│   │   ├── Cart (checkout flow)
│   │   ├── AddProduct (admin)
│   │   ├── UpdateProduct (admin)
│   │   ├── Product (single product view)
│   │   ├── OrderHistory (list orders – filtered by user)
│   │   ├── PaymentSuccess
│   │   ├── PaymentCancel
│   │   └── Admin pages: /admin, /admin/users, /admin/orders (role-protected)
│   └── ToastProvider (global notifications)
└── WebSocketProvider (real-time order/payment updates)
```

### Key Patterns
- **Global Cart**: Stored in Context + localStorage persistence
- **Product Fetch**: Single source in `Context.jsx` `refreshData()` on mount
- **Real-time**: WebSocket listeners update order status automatically in OrderHistory
- **Toast**: Centralized notifications via `showToast(msg)` from any component
- **Authentication**: JWT stored in localStorage; `PrivateRoute` component protects admin/user routes; role-based navigation visibility
- **Order Ownership**: Backend filters orders by authenticated user ID; admins bypass filter

## 11. Troubleshooting

### Backend won't start
- **Port 8080 in use:** `lsof -ti:8080 | xargs kill -9`
- **Database connection refused:** Ensure PostgreSQL is running: `sudo service postgresql start`
- **Maven build fails:** Delete `target/` and run `./mvnw clean install`

### Frontend won't start
- **Port 5173 in use:** `lsof -ti:5173 | xargs kill -9`
- **Module not found:** Run `npm install`
- **Axios base URL:** Check `src/axios.jsx` points to `http://localhost:8080/api`

### WebSocket not connecting
- **JWT required:** Frontend passes token via query param (`?token=...`). Ensure user is logged in.
- **Handshake validation:** Backend uses `JwtHandshakeHandler` to validate token during SockJS handshake.
- CORS: Backend allows all origins (`@CrossOrigin`). Ensure backend is running before frontend.
- Check browser console for errors.
- Test endpoint: `http://localhost:8080/ws/info` (SockJS handshake) should return 200

### Stripe webhook not working
- Ensure `stripe.webhook.secret` matches the webhook signing secret in Stripe Dashboard.
- Webhook endpoint **must be publicly accessible** (use ngrok for local dev):  
  `stripe listen --forward-to localhost:8080/api/payment/webhook`
- **Webhook endpoint is unauthenticated** (permitted in SecurityConfig). Check backend logs for 401/403.
- Verify webhook logs in Stripe Dashboard → Developers → Webhooks.
- If order status stuck PENDING, check if webhook events were delivered (retry from Stripe Dashboard).

### Database issues
- Tables not created: Check `spring.jpa.hibernate.ddl-auto=update` is set.
- See SQL logs: `spring.jpa.show-sql=true`
- Connect manually: `psql -U mursalin -d project_showcasing`

## Appendix: WebSocket Authentication

### JWT Token in Query Parameter
Since SockJS doesn't support custom headers in the WebSocket handshake, the JWT token is passed as a query parameter:

**Frontend connection URL:**
```
http://localhost:8080/ws?token=<JWT_TOKEN>
```

**Backend validation:**
1. `JwtHandshakeHandler` extracts `token` from query string
2. Validates token via `JwtService.validateToken(token)`
3. If valid, sets `Principal` on the WebSocket session (accessible via `@AuthenticationPrincipal` in STOMP message handlers if needed)
4. If invalid/missing, connection proceeds anonymously (no principal)

**Security considerations:**
- Token in URL may be logged in server access logs → use HTTPS in production
- Token is URL-decoded ( UTF-8 ) and validated server-side
- WebSocket endpoint itself is publicly accessible (`permitAll()` in `SecurityConfig`); authorization is enforced at application layer via `@PreAuthorize` on message handlers (if implemented)

**Reconnection on auth change:**
- `WebSocketContext` watches `[token]` dependency → reconnects automatically on login/logout/token refresh
